# NEURON V3.8 — Multi-Monitor, Multi-App & Adaptive Skills

**Date:** 2026-07-30  
**Status:** Implemented and baseline-verified  
**Continues:** V3.1–V3.7 (ContextEngine → Adaptive AgentLoop)

## Summary

V3.8 upgrades multi-monitor reasoning to use live geometry (including **foreground**), adds staged **multi-application** planning with per-stage verification, and converts skill learning to **semantic adaptive procedures** that refuse passwords/tokens/coordinates/screenshots.

---

## 1. Multi-monitor reasoning

### Understanding (live geometry — no hardcoded coordinates)

| Reference | Resolution |
|-----------|------------|
| `main` / `primary` | Primary display from OS |
| `monitor 1` / `2` / word numbers | Numeric id from enum |
| `other` / `another` / `secondary` | Not current (sticky focus → FG window → non-primary) |
| `left` / `right` | Spatially leftmost / rightmost by center-x |
| `foreground` / `current` / `this` | Monitor containing the foreground window |

### Changes
- `neuron/windows/monitors.py` — foreground role annotation; `resolve_monitor_ref` + `extract_monitor_ref` + `normalize_monitor_arg`
- `normalize_monitor_arg("other")` keeps the NL token (never rewrites to hardcoded `2`)
- CapabilityRouter move/open-on-monitor patterns preserve relative tokens
- ReferenceResolver accepts foreground / left / right / main tokens

### Act-time placement
`move_window_to_monitor` still places windows using **work-area geometry** from the OS, then verifies window center on the resolved monitor.

## 2. Multi-application goals

### Example
> Open Chrome on monitor 2, search YouTube for Blender animation tutorials, play the first result, and open Blender on monitor 1.

### Composer
`neuron/v3/multi_app.py` → `compose_multi_app_plan()` builds staged steps:

1. `open_app` Chrome → `move_window_to_monitor` (2)  
2. `open_app` Blender → `move_window_to_monitor` (1)  
3. `browser_search` YouTube  
4. `play_result` (first)

Each step includes `target` + `expected_result` so AgentLoop **verifies every stage** (V3.7 observe→act→verify→recover).

### Routing
CapabilityRouter runs multi-app composition **before** single-action patterns when `looks_multi_app()` is true (`capability=multi_app.workflow`).

Planner hints updated for multi-monitor tokens and staged multi-app plans.

## 3. Adaptive semantic skills

### Principle
Skills are **semantic procedures**, not coordinate recordings.

Example builtin: `blender.start_render` / `start_blender_render(project)`

| Semantic step | Role |
|---------------|------|
| `blender.open_project` / `open_app` | Open target |
| `wait` / `blender.wait_for_app` | Wait for app |
| `press_keys` F12 / `blender.trigger_render` | Trigger render |
| `find_element` / `blender.verify_render` | Verify started |

Window moves do not break skills because steps use **names / tools**, not x,y.

### Learning pipeline (`neuron/learning/semantic.py` + `procedures.py`)
- Prefer UIA `name` / `automationId` → `click_element`
- **Drop** raw `click{x,y}` and screenshot/pixel fields
- **Refuse** passwords, tokens, credentials, private form fields
- `clicks_to_steps` no longer emits coordinates
- `save_procedure` marks `semantic: true` and records sanitize warnings
- Param binding: `{project}` placeholders via `bind_params`

### Domain skills added
- `blender.wait_for_app`
- `blender.trigger_render`
- `blender.verify_render`
- `blender.start_render`

### Privacy / config
- `click_record.store_pixels` default → **false**
- Never persists: passwords, tokens, credentials, private fields, unnecessary screenshots
